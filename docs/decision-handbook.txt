Decision: Complete write flow
Confirmation: Read the daily member flat file and redemption JSON file from local input directories. Write Raw Delta, Staging Delta, Target Delta, and export files.

Decision: Processing platform
Confirmation: Use Docker, Apache Spark, and Delta Lake. Do not use Snowflake or MinIO.

Decision: Local storage
Confirmation: Mount the host data/ directory in both Spark containers at /opt/skypoints-data/. Use local file:/// Delta paths.

Decision: Country targets
Confirmation: Store members in one partitioned Delta target by country_code. Do not create physical country tables dynamically.

Decision: Country outputs
Confirmation: Produce country-specific views or export files from the target Delta table.

Decision: Generate Sample files using Agent
Confirmation: Use AI Agent to defer work of generating sample records to be ingested - Generated txt files using Agent and JSON files for redemption

Decision: Raw layer Control table: source_path and ingestion time - we will use this to filter out those records that have already been ingested

Decision: Raw layer schema - we will use a simple schema with the following fields: source_path, raw_record, and ingestion_time and then split the raw_record on pipe to get the individual fields for the staging layer

Decision: Staging layer schema - we will use a schema with the following fields: member_id, first_name, last_name, email, country_code, and ingestion_time. We will also add a partition column for country_code to optimize queries.

Decision: Target Layer - we will create a consolidated target layer with the latest member records for member_id and then we can create country-specific views or export files from this target layer. We will use Delta Lake's MERGE operation to update the target layer with new records from the staging layer.
